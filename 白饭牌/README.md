# 白饭牌

37 张牌的三列叠放对战游戏。本仓库包含**可复用的纯逻辑引擎**、**三档 AI**、**模拟/调参工具**，以及一个**双击即玩的单文件网页版**。

规则定稿见 [`规则定稿.md`](./规则定稿.md)。

---

## 快速开始

### 玩一局（推荐）
直接双击打开 **`白饭牌.html`** —— 零依赖、无需服务器、无需联网。

开局弹窗里先选**对局模式**：

| 模式 | 说明 |
|---|---|
| **人机对战**（默认） | 你操作玩家 1，AI 操作另一方。你不点，AI 绝不会替你出牌。 |
| **双人同机** | 两个座位都由人操作，本地轮流；视角自动跟着当前行动方切换。 |
| **AI 自动演示** | 两边都由 AI 操作，纯观战，用来观察技能与 AI 表现。 |

然后选 AI 难度，开始对局。开局会随机亮出 3 个技能，**后手先选**、先手再选。
接着按顺序走完开局流程：先手的开局选牌（如观星）→ 后手指定禁列 → 先手走出第一手（禁列只对第 1 回合有效）。
技能面板显示双方技能与剩余次数，可用时直接点按钮发动。

想换模式：顶部「重开」按钮，或结算界面的「切换模式」。

若改了 `src/` 里的引擎或 `web/` 里的 UI，重新生成：

```bash
node tools/build.mjs
```

### 跑测试
```bash
node tools/test.mjs          # 规则断言 + 随机对局不变量
node tools/skill-test.mjs    # 技能断言 + 带技能的自动对局
node tools/ui-test.mjs       # 界面行为（在 Node 里跑真实产物，无需浏览器）
```

### 看 AI 强弱分层
```bash
node tools/tournament.mjs 200            # 无技能
node tools/tournament.mjs 200 1 --skills # 带技能
```

## 引擎设计约定

1. **纯函数**：`applyAction(state, action)` 永不修改入参，总是返回全新状态。因此可以放心做搜索、回放、悔棋。
2. **随机可注入**：引擎与 AI 都不调用 `Math.random`，随机源从外部传入，所以整局对局可以用种子完整复现。
3. **规则集中在 `rules.js`**：UI、AI、模拟器都只通过 `legalActions` / `canPlaceAt` 理解规则，改规则只需改一处。
4. **引擎与表现分离**：`src/` 不含任何 DOM 代码，可无头运行；`web/ui.js` 只负责渲染与点击。
5. **零依赖**：全部 ES module，Node 与浏览器共用同一份源码。

### 常用 API

```js
import { createGame, applyAction, legalActions, isOver, cardCounts, summarize } from './src/engine/game.js';

let state = createGame({ seed: 123 });          // 开新局（可复现）
const actions = legalActions(state);            // 当前行动方的全部合法着法（含过牌）
state = applyAction(state, actions[0]);         // 执行着法，得到新状态
cardCounts(state).total;                        // 恒为 37，可用于自检
summarize(state);                               // 一行摘要，便于打日志
```

```js
import { BUILTIN_PROFILES, createProfile } from './src/ai/profiles.js';
import { createRng } from './src/engine/random.js';

const action = BUILTIN_PROFILES.hard.decide(state, state.current, createRng(7));
```

const 我的AI = createProfile({

## AI 三档的设计

| 档位 | 做法 | 实测强度 |
|---|---|---|
| 简单 | 在合法着法里随机选 | 基准 |
| 普通 | 真实局面上搜索 **2 层**，能算出对手最佳回应 | 对简单 63.5% |
| 困难 | 真实局面上搜索 **3 层** | 对简单 75.5% ／ 对普通 62.5% |

（以上为 `node tools/tournament.mjs 200` 的结果，每对 200 局、交替先后手、无规则违规。）

两个通过实测量出来的结论，都写进了代码注释：

1. **加深搜索确实有效**：d2 → d3 带来 63.3% 的直接胜率提升，d3 → d4 收益趋平，
   所以困难档取 d3（既有明显提升，单步耗时仍在 ~40ms）。
2. **不要猜对手手牌**：把对手手牌换成未知牌池里的牌（哪怕只换一部分），胜率会从
   ~60% 掉到 ~38%。这个游戏对"某张关键牌是否在对手手里"极其敏感，
   **错误的建模比不建模更糟**，因此三档都只用公开信息，强度靠深度拉开。

想复现或继续调参：

```bash
node tools/tournament.mjs 200   # 三档两两对打，输出分层结论
node tools/ai-lab3.mjs 60       # 深度实验：d2 / d3 / d4 谁更强
node tools/ai-lab.mjs 60        # 建模实验：采样 vs 真实手牌
node tools/sweep.mjs 50         # 配置扫描
node tools/diagnose.mjs 100     # 对局结构诊断（胜负方式、过牌质量）
```

## 单文件网页版

`tools/build.mjs` 把 `web/index.html` + `web/ui.js` + `src/` 下的 8 个模块按依赖顺序
拼接进一个普通 `<script>`（去掉 import/export），生成 **`白饭牌.html`**。

- 为什么这么做：浏览器不允许 `file://` 协议加载 ES module（CORS），内联成普通脚本后
  **双击即可运行**，不需要起服务器。
- 打包时会检查跨模块的顶层标识符冲突，重名直接报错，避免静默出错。
- 调试时浏览器控制台可用 `window.BaiFan` 访问引擎函数。

### 界面测试：在 Node 里跑真实产物
```bash
node tools/ui-test.mjs
```
`tools/mini-dom.mjs` 实现了一个最小可用的 DOM（元素树、classList、hidden、
innerHTML 解析、事件、假时钟），因此**不需要浏览器、不需要任何权限**就能把
`白饭牌.html` 里打包好的界面代码真的跑起来，然后模拟点击验证：

- 后手时禁列提示条可见、先手时不出现、选择完成后消失
- 先手持有观星时，开局选牌不会被算成一回合（禁列因此仍然生效）
- 牌堆叠放只露牌头，点开能看到完整牌堆与每张牌的说明
- 选中某张牌后，只有这张牌真正能放的列被高亮
- 限制横幅按状态切换样式
- 能自动打完多局并弹出结算

> 已删除并由上面的迷你 DOM 方案取代（更快、可复现、无需权限）。

## 规则要点（完整版见 规则定稿.md）

- **牌库**：普通 0–5 各 4 张 + 紫 0×1 + 黑 5×2 + 浅/深 E 各 3 + 浅/深 M 各 2 = 37。
- **每列只有最上方那张生效**，被压住的牌不受任何影响。
- **数字**：顶端 0–3 接 +1/+2；顶端 4 只能接 5（n+2 是 6，牌库没有 6）；顶端 5/黑 5 只接 0；顶端紫 0 按 0 计只接 1/2。
- **浅 E** 炸顶端 0–4；**深 E** 炸顶端 0–5，但**黑 5 免疫**（炸不掉它，其上也放不了 E）；基底那张永远不可被炸。
- **浅 M** 让对方下一回合只能出数字牌且不能放这一列；**深 M** 只能放这一列的数字牌。
  M 放完立即出局，效果只作用于对方紧接的那一个回合（对方过牌也照样消耗）。
- **紫 0 限锁**：任意一列顶端是紫 0 时，全场只能出数字牌，优先级高于一切 E/M 效果。
- **过牌**：牌堆有牌则自己抽 2 张、对方抽 1 张；牌堆空则直接换手。
- **胜负**：出完手牌即胜；牌堆抽空且双方连续各过 2 次牌即结算，手牌少者胜（多留一个回合的缓冲）。

## 技能系统

技能**独立于卡牌**：开局随机亮出 3 个候选，后手先选、先手再选，每人 1 个，双方技能公开。
开局流程固定为：先手的开局选牌（观星）→ 后手指定禁列 → 先手第一手；**观星这类开局选牌不占回合**。
优先级：**紫 0 全局限锁 > 禁列 > 下回合限制 > 技能 > 常规规则**。

| 技能 | 类型 | 效果 |
|---|---|---|
| 消却 | 主动×1 | 移除任意牌堆顶端（不能是基底），**不占用行动** |
| 看破 | 主动×2 | 观看对方手牌，**不占用行动**（只看发动当回合的那一眼） |
| 沉默 | 主动×2 | 对方下一回合不能放置 E/M、**也不能使用主动技能**，**不占用行动** |
| 创生 | 主动×1 | 选一张 0–5 凭空加入**对方**手牌（凭空造牌，牌库总数 +1） |
| 禁锢 | 主动×1 | 对方下回合只能在这一列放数字牌（与深 M 同效果，AI 选列也共用同一套算法） |
| 睡眠 | 主动×2 | 跳过一次行动（双方都不抽牌） |
| 甩手 | 主动×1 | 弃一张手牌（进入已出局区）；**丢掉最后一张手牌等同于出完手牌，立即获胜** |
| 爆弹 | 被动 | 你放置 E 的下一回合，对方的**所有牌（数字 / E / M）都只能放在那一列** |
| 观星 | 被动 | 游戏开始时**随机拿走对方 2 张手牌**，然后选 2 张手牌交给对方（一进一出，双方手牌数不变） |
| 威严 | 被动 | 你没放过 E/M 时，对方也不能放 E/M |
| 荆棘 | 被动 | 对方不能在你刚放下的数字牌上放数字牌 |
| 汇流 | 被动 | 你过牌改为抽 3 张，然后**从这 3 张里选 1 张**交给对手（不能从整副手牌里挑垃圾） |

设计要点：

- **统一的「下回合限制」机制**：M 魔法、禁锢、荆棘、爆弹、沉默共用同一套限制结构，
  加新技能只需填不同字段（列约束 / 禁牌型 / 例外牌型），不用改判定代码。
  **限制按玩家分槽存储**（`state.restrictions[player]`），互不覆盖，同一人可同时背多条；
  另有 `ready` 标记保证"自己回合内挂给对手的限制"不会被自己的回合结束顺手清掉。
- **弃牌复用「已出局区」**，不新增区域。
- **凭空造牌**（创生）：造出来的牌登记在 `state.createdCards`，牌数守恒的基线随之抬高（37 → 38）。
- **交互式选牌**：观星/汇流/创生共用一套"给对手哪张牌最难受"的判断
  （`pickWorstCardForOpponent`：优先给当前放不出去的数字牌，紫 0 限锁下改给 E/M，否则按落点数从少到多）。
- **AI 选技**：按实测强度表 `SKILL_STRENGTH` 做 softmax，档位由 `config.skillSharpness` 控制随机程度
  （简单 0.7 / 普通 1.6 / 困难 3.0）。UI 层不再维护自己的选技启发式。
- **加新技能**：在 `src/skills/skills.js` 里 `defineSkill({...})` 即可，引擎主流程不用改。
